# 微信消息提取器综合重构设计

> 本文是 `2026-08-03-wechat-extractor-ui-workflow-redesign-design.md` 的修订版，合并已确认的页面方案与工程优化项，并作为后续实施计划的唯一依据。

## 1. 目标与范围

将现有三个独立页面重构为清爽、高效的单页向导，同时修复影响安装、正确性、安全、性能和维护性的基础问题。最终流程应支持连接微信、选择群聊与日期、预览任务、导出 Excel，以及顺畅返回任意已完成步骤。

本次允许调整 Web 路由、模板、会话状态、任务编排和相关核心模块，但不改变任务消息格式、群聊到 Sheet 的业务含义及 Excel 的主要列结构。

## 2. 已确认的产品设计

- 视觉采用“清爽效率型”：白色内容面板、墨色主文字、克制的微信绿和轻量阴影。
- 使用一个持久页面外壳，中间工作区通过 htmx 无刷新替换。
- 顶部步骤条始终可见；已完成步骤可点击返回，当前步骤高亮，未来步骤锁定。
- 每一步成功后启用“下一步”，由用户主动确认后推进，不自动跳转。
- 第二步采用单一主内容区，不设置右侧摘要栏。
- 返回或刷新后保留仍然有效的连接、群聊、日期、Sheet、预览和导出设置。

## 3. 页面架构

`base.html` 提供应用顶栏、隐私状态、步骤条、工作区和固定操作栏。三个步骤改为 Jinja partial，由统一向导路由返回。后端不再拼接业务 HTML，动态内容全部由模板自动转义。

```text
templates/
├── base.html
├── wizard.html
├── components/
│   ├── stepper.html
│   ├── status_message.html
│   └── wizard_actions.html
└── steps/
    ├── connect.html
    ├── select.html
    └── preview.html
```

服务端保存当前步骤、完成状态和表单数据。切换步骤时同步浏览器历史；刷新时恢复最近可访问步骤。后端必须校验前置条件，不能只依赖前端锁定。

## 4. 三步流程

### 4.1 连接微信

自动检测客户端版本、进程、数据目录和消息分片，并用集中状态列表展示。检测成功后启用“连接并继续”；手动密钥收进“高级选项”。失败时显示原因、恢复建议和重试按钮，不清空已经发现的信息。

### 4.2 选择数据

按纵向顺序展示搜索、开始/结束日期、群聊列表、选择摘要和导航栏。每行包含单选状态、群名、最近消息时间、Sheet 下拉框和消息数。选择群聊不立即跳转；只有群聊、合法日期和有效 Sheet 均确定后才启用下一步。

### 4.3 预览与导出

先展示群聊、日期、Sheet 和识别数量，再按日期列出可勾选任务。输出位置位于列表下方；AI 与语音等低频选项折叠展示，并明确外部数据传输。导出期间禁止重复提交，原位展示阶段和百分比；失败时保留全部选择并允许重试。

## 5. 导航与状态

步骤状态为 `locked`、`available`、`active`、`completed`。连接成功开放步骤二，预览生成后开放步骤三。返回上游后，只有修改关键字段才使相关下游结果失效；未修改时直接恢复原状态。浏览器前进/后退与步骤条一致，非法越级访问由服务端拒绝并重定向到最近可用步骤。

## 6. P0：正确性与可运行性前置项

- 修复语音导出引用未定义 `s_date`、`e_date`，统一从已校验 session 读取日期；单条失败记录原因而非静默忽略。
- 实现页面已引用但缺失的 `/api/key/validate`，覆盖成功、格式错误和无效密钥。
- 明确 Excel 同日期采用“更新现有行”而非无条件追加，使实现与测试意图一致；Sheet 不存在必须报错。
- 修复仅提供文件名时创建空目录失败；统一校验日期顺序、Sheet、输出目录和 `.xlsx` 后缀。
- 建立可重复安装环境。声明代码实际使用的 `pywxdump`、`pycryptodomex` 和测试所需 `pytest`，迁移至 `pyproject.toml`，记录受支持 Python 版本。

## 7. P1：安全与隐私

- 通过 Jinja 自动转义群名、消息、Sheet、路径和错误；用户只看到安全错误摘要，完整异常写入日志。
- 导出仅允许配置目录或用户明确授权的位置，防止任意文件覆盖。
- 写入 Excel 前中和以 `= + - @` 开头的公式注入内容。
- 默认仅绑定 `127.0.0.1`；若开放局域网，必须增加认证、CSRF、安全 cookie 和访问控制。
- AI 与语音默认不发送数据。首次启用时列出提供商、发送内容和隐私影响并取得确认；页脚不得无条件声称“数据不上传”。

## 8. P1：资源生命周期与任务进度

- session 增加 TTL、容量限制与清理机制；重连、过期和应用关闭时关闭 SQLite/Excel 并删除临时解密文件。
- SSE 以独立任务 ID 区分导出，事件使用 JSON，不再用 `|` 拼接；限制队列并在断连、完成或取消时注销。
- 后台任务需要登记、取消和关闭机制，禁止同一 session 重复启动导出。
- 转写结果和分析结果按任务 ID 保存，重复导出不能再次追加到原 session 数据。

## 9. P1：性能与可靠性

- 鉴权后缓存群聊、联系人名称和 Sheet 元数据；搜索只过滤缓存，不重复解密联系人库或打开工作簿。
- 数据库按 4096 字节页流式解密，避免整库载入内存；每个分片执行关键表验证并报告被跳过的分片。
- 扫描、解密、SQLite 查询、SILK 解码和 Excel 写入通过线程池或后台任务运行，避免阻塞 FastAPI 事件循环。
- AI/语音请求设置明确超时、有限重试和并发上限；失败降级必须可见且可追踪。

## 10. P2：架构与工程质量

- 拆分 `app.py`：HTTP 路由进入 `routers/`，向导状态与业务编排进入 `services/`，请求/响应模型进入 `schemas/`，HTML 只由模板负责。
- 统一数据库访问路径。评估并删除或迁移未被主流程使用的 `DBDecryptor`、`MessageFetcher`、`KeyExtractor` 旧实现，避免测试与生产走不同代码。
- 引入 Ruff 和类型检查，清理未使用导入、宽泛 `except Exception` 和无日志 `pass`。
- 增加 CI，执行依赖安装、单元测试、FastAPI 集成测试和静态检查；Windows/微信依赖通过协议接口、模拟对象和脱敏夹具隔离。

## 11. 反馈、可访问性与响应式

- 加载使用局部骨架或进度提示，错误紧邻控件并包含恢复动作。
- 颜色不是唯一状态信号，同时使用图标和文字。
- 输入具有可见标签和键盘焦点，群聊列表支持键盘操作，动态更新使用 `aria-live`。
- 桌面内容宽度约 840–960px；窄屏时筛选和列表改为单列，底部操作栏保持可见。

## 12. 测试策略

- 单元测试覆盖步骤转换、上游修改导致下游失效、日期/Sheet 校验、Excel 同日期更新和公式中和。
- FastAPI 集成测试覆盖三个 partial、手动密钥路由、越级访问、刷新恢复、导出路径限制和重复提交。
- 模板测试验证动态文本转义，以及加载、空状态和错误状态。
- 浏览器流程测试覆盖完整前进、逐步返回、刷新恢复、修改后重新预览和导出失败重试。
- 数据库测试覆盖分片失败隔离、流式解密验证和资源清理；AI/语音使用模拟 HTTP 服务验证超时与重试。

## 13. 实施顺序

1. 完成依赖闭环、P0 缺陷和关键回归测试。
2. 建立向导状态模型、资源生命周期和安全输出边界。
3. 实施页面外壳、三个步骤 partial 和无刷新导航。
4. 加入缓存、流式解密、后台任务、完整测试与 CI。

每个阶段必须独立通过测试后再进入下一阶段，避免新界面掩盖旧流程错误。

## 14. 成功标准

项目可由文档化命令可靠安装和测试；用户可无整页跳转完成三步并安全返回；刷新不丢失有效状态；错误不清空表单；资源会被回收；动态内容和 Excel 输出均经过安全处理；重复搜索与导出不会造成明显阻塞或数据重复；桌面与窄屏均可完成全部核心操作。
