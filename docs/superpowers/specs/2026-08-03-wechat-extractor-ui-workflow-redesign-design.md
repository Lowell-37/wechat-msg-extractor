# 微信消息提取器页面与流程重构设计

## 1. 目标与范围

将现有三个独立页面重构为清爽、高效的单页向导，统一视觉语言并解决步骤切换不连贯、选择状态易丢失、主要操作不明确的问题。重构覆盖连接微信、选择数据、预览导出三个步骤，以及加载、空状态、错误和导出进度反馈。

本轮不改变数据库解密、消息解析、AI 分析和 Excel 写入的业务规则；只为支持新流程调整 Web 路由、模板组织和会话状态接口。

## 2. 已确认的设计决策

- 视觉采用“清爽效率型”：白色内容面板、墨色主文字、克制的微信绿状态色和轻量阴影。
- 使用一个持久页面外壳，中间工作区通过 htmx 无刷新替换。
- 顶部步骤条始终可见；已完成步骤可点击返回，当前步骤高亮，未来步骤锁定。
- 每一步成功后只启用“下一步”，由用户主动确认后推进，不自动跳转。
- 第二步使用单一主内容区，不设置右侧选择摘要栏。
- 返回上一步时保留已连接数据库、群聊、日期、Sheet、解析结果和导出设置。

## 3. 页面架构

`base.html` 提供应用顶栏、隐私状态、步骤条、工作区和固定操作栏。三个步骤改为可独立渲染的 Jinja partial，由统一的向导路由返回。后端不再用 Python 字符串拼接业务 HTML，所有动态内容通过模板自动转义。

建议模板结构：

```text
templates/
├── base.html
├── wizard.html
├── components/
│   ├── stepper.html
│   ├── status_message.html
│   └── wizard_actions.html
└── steps/
    ├── connect.html
    ├── select.html
    └── preview.html
```

服务端 session 保存当前步骤、各步骤完成状态和表单数据。切换步骤时同时更新 session 与浏览器历史；刷新页面后由 session 恢复最近可访问的步骤。后端必须校验步骤前置条件，不能仅依赖前端锁定。

## 4. 步骤设计

### 4.1 连接微信

页面自动检测微信客户端版本、进程状态、数据目录和消息分片，并用三条状态行集中展示。检测成功后启用“连接并继续”；连接成功后用户点击“下一步”进入选择数据。

手动密钥属于低频恢复操作，收进“高级选项”。自动或手动连接失败时，在对应区域显示可执行建议和“重新检测/重试”按钮，不清空已经发现的环境信息。

### 4.2 选择数据

页面按纵向顺序展示标题、搜索框、开始/结束日期、群聊列表、选择摘要和导航栏。群聊列表每行包含单选状态、群聊名称、最近消息时间、目标 Sheet 下拉框和相关消息数。

选择群聊不立即跳转。系统自动匹配 Sheet，未匹配时要求用户在同一行修正。只有群聊、合法日期范围和有效 Sheet 均已确定后，底部“下一步：预览任务”才可用。列表下方以一行摘要确认最终选择。

### 4.3 预览与导出

页面先展示群聊、日期范围、目标 Sheet 和已识别数量，再按日期列出任务。任务默认选中，允许取消不需要导出的条目。输出文件位置在任务列表下方设置；AI 分析和语音转写等低频选项折叠展示，并明确可能向外部 API 发送数据。

点击导出后，主按钮进入不可重复提交状态，并在原位置展示阶段、百分比和文字说明。成功后提供输出路径和“打开所在目录/重新导出”操作；失败时保留全部选择并允许重试。

## 5. 导航与状态流

步骤状态为 `locked`、`available`、`active`、`completed`。初始仅步骤一可用；连接验证完成后开放步骤二；预览数据生成后开放步骤三。返回已完成步骤不会自动清除后续状态，但如果用户修改了上游关键字段，相关下游结果必须失效并在再次前进时重新生成。

浏览器前进和后退应与步骤条一致。服务器拒绝越过未完成前置步骤的请求，并返回当前可访问步骤及友好提示。导出任务进行中时禁止重复启动，但允许用户继续查看当前进度。

## 6. 反馈、可访问性与响应式

- 加载状态使用局部骨架或进度提示，不让整个页面闪烁。
- 错误信息紧邻相关控件，包含原因、恢复建议和重试动作。
- 颜色不是唯一状态信号，同时使用图标和文字。
- 所有输入具有可见标签和键盘焦点；群聊列表支持键盘选择。
- 桌面端内容最大宽度约 840–960px；窄屏下筛选项和列表字段改为单列，底部操作栏保持可见。
- 动态更新区域使用合适的 `aria-live`，导出进度提供文本百分比。

## 7. 安全与隐私

所有群名、消息、路径、Sheet 名和错误内容都由 Jinja 自动转义。输出路径限制在配置的导出目录或经过明确授权的文件位置。写入 Excel 前处理公式注入风险。页脚隐私文案必须区分“本地处理”和启用 AI/语音服务后的外部传输，并在首次启用时取得明确确认。

## 8. 测试策略

- 单元测试覆盖步骤状态转换、上游修改导致下游失效、日期与 Sheet 校验。
- FastAPI 集成测试覆盖三个 partial、非法越级访问、返回状态恢复和导出重复提交。
- 模板测试验证动态文本被转义，错误、空状态和加载状态均可渲染。
- 浏览器流程测试覆盖完整前进、逐步返回、刷新恢复、修改后重新预览和导出失败重试。
- 响应式和键盘操作进行人工验收；主要页面保存桌面与窄屏截图用于回归比较。

## 9. 成功标准

用户能够在不发生整页跳转的情况下完成三步流程；任意已完成步骤均可安全返回；返回或刷新不会丢失有效选择；不能越过未完成步骤；错误不会清空表单；所有动态内容经过安全转义；桌面与窄屏均能清晰完成核心操作。
